**Trigger:** QA on Multishop custom-domain connect / disconnect where `project_domains` is the source of truth (PR #44800 and later): connect wizard, Domain transfer page, DNS page, storefront routing of aliases.

**Rule:** Surfaces: connect wizard `/admin/connect-custom-domain/?id=<marketId>` (step 1 domain + two method cards → submit; step 2 = `dns-records` `validate:0` on mount, "Check settings" = `validate:1`); Domain transfer `/admin/dns-transfer/?id=<marketId>` shows the connected host with **Edit** (a placeholder `alert()` — never click it, it freezes CDP) and **Disconnect** → React ConfirmModal "Disconnect domain?" (Keep / Disconnect) → `POST /admin/multi-shop/disconnect-domain-from-market/` `{id}` → lands on `/admin/dns/?id=` with "Your e-shop is currently running on the Shoptet domain 704384-<id>.myshoptet.com". Disconnect on a market without a custom domain is a silent 200. Prove which market a host serves with `curl -sk … | grep -oE '<html[^>]*>|<title>[^<]*</title>'`: `lang` plus the language-flag `<title>CZ</title><title>SK</title>` rows identify the market (single-language markets show no flags). After EVERY connect also probe the market's internal alias `704384-<marketId>.myshoptet.com.test`: on #44800 an invalid (NXDOMAIN) custom row made the alias 301 to the dead host while the view kept the alias canonical. DNS-valid test domain on the dev stack (real lookups): `test-shoptet.jakubkulhan.cz` (CNAME → www.myshoptet.com, passes the core_records higher-order strategy) — it is project 704384's own market-107 domain (row 44714), so disconnect it first, connect it to the target market, then restore by SQL (`activeTo=NULL, isCanonical=1` on 44714, `isCanonical=0` on the alias 866261, delete the QA rows). NXDOMAIN hosts (`qa<ticket>-nx.cz`) give `isRoutingValid=0` rows. The failsafe SSL requester logs `Failed to request SSL certificate … change-me.ssl-certificate-api.invalid` on every valid connect/check locally — expected, not a finding. New rows for a brand-new sales channel get `marketId = 0` (`ProjectDomainWriteRepository::resolveMarketId` reads it from existing rows of the channel).
