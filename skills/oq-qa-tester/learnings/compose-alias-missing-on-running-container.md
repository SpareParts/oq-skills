**Trigger:** Every shop on the dev stack answers `500` with `RedisException: Redis server <host> went away` (or any "went away"/name-resolution failure naming an infrastructure host), while `docker compose ps` shows every container up and healthy.

**Rule:** A network alias added to `docker/docker-compose.yml` on master does NOT reach a container that has been running since before that commit. Diagnose without guessing: `./docker/dev compose exec -T www sh -c 'getent hosts <host>'` fails while every sibling alias resolves, and `docker inspect <container> --format '{{json .NetworkSettings.Networks}}'` shows the live alias list missing the new name. Find the commit with `git log -S '<host>' -- docker/docker-compose.yml`. Fix is `./docker/dev compose up -d --force-recreate <service>` — named volumes survive, so KeyDB/DB data is kept. Concrete case 2026-09-17: `central-keyval.local` from master `aa7c42970e4` (#44745, CZ3SRE1-240); the first request 500s fast and later ones hang on DNS retry, which looks like the log-flock hang but is not (check `flock -n` first — it comes back FREE). Report it as environmental and ask before recreating; then re-verify with `curl -sk -o /dev/null -w '%{http_code}'` on a storefront AND `/admin/login/`.
