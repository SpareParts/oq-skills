**Trigger:** A scenario needs the module deactivation guard (`ModulesHelper::couldBeTurnedOffMessage`) exercised from the merchant's chair.

**Rule:** `/admin/moduly/` is a Superadmin section — a merchant/owner login gets "Nemáte dostatečná oprávnění". Use the tariff-change flow on `/admin/tarif-platba-a-doklady/` instead: pick a lower tariff whose module set drops the module under test and submit — `couldBeDowngraded` runs every dropped module's guard and shows the block messages as error notifiers without changing anything. Check the target tariff's module set first in `st_crm`: `cms2_tariffs_services_rel` joined to `services` with `serviceType = 2` (TYPE_MODULE). For a "guard now passes" scenario, make sure ANOTHER active module still blocks the downgrade (on fenix, `wholesale` blocks while B2B customer groups exist) so the tariff can never actually change.
