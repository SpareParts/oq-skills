**Trigger:** Using `/admin/login/` on a SECONDARY market's own domain (e.g. `rofl2.myshoptet.com.test`) as the "non-storefront runtime" control while testing a storefront-only branch on a live host.

**Rule:** The admin on a secondary-market domain always answers `301 http://<primary domain>/admin/login/` (multishop's own hop to the primary-domain admin), never 200, with or without any redirect row. Take the identical response before/after the seeded state as the control, plus the blob content (`"id":<projectId>` present = project resolved; the new key riding on it); do not read the 301 as the redirect under test. Seeding a redirect row for a live domain works with one SQL insert (same `projectId`/`marketId`, `redirectionTargetPattern` set) but you must `DEL env:<host>` before and after, otherwise the storefront of that live market keeps redirecting for up to 30 days.
