**Trigger:** Asserting what the storefront does when a live host has no active `routing_domains_active` row — a closed/missing `project_domains` row, an `isRoutingValid = 0` row, or the "project_domains not complete fleet-wide" deploy gate (PR #44800 and later).

**Rule:** The outcome depends on HOW the host resolves to the project, and the two cases look nothing alike. (1) Host matches `projects_active.url` (typically the primary market's domain): the project resolves, `MarketReadRepository::findByDomain` returns null, `MarketDetectionMiddleware` catches `MarketNotFoundException` and falls back to the legacy project URL — the page answers **200 but renders UNSCOPED**, i.e. with project-wide configuration instead of the sales channel's. (2) Host resolves only through `project_domains` (any secondary market domain): the project is not found at all and the storefront 302s to the InactiveProjectRouter. So never read PASS/FAIL off the status code alone here. The cheapest scope assertion is the storefront language switcher: `curl -sk … | grep -oE '<title>[A-Z]{2}</title>'` returns the channel's assigned languages when scoping works and the project's full `languages WHERE isVisible = 1` list when it collapsed (observed on 704384: 4 flags `CZ GB NL PT` healthy vs 8 flags `CZ GB SI PL RS PT NL UA` unscoped). Take the healthy flag list first as the control.
