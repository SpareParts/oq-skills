**Rule:** Rows live in `st_cms.domain_redirects` keyed by `projectId` (not a per-project silo). The list filters project rows by channel: a row belongs to the market iff `salesChannelId` matches or its source/target host shares the registrable domain with the market's domain (`SalesChannelMatcher.hasSameRegistrableDomain`) — pre-existing rows with foreign registrable domains (fenix ships `fenix.shoptet.cz`) are invisible on the list and their detail 400s, so seed your own rows via the Add modal (sets `salesChannelId`). Detail/update do a live DNS lookup on the SOURCE host per request (nothing persisted): NXDOMAIN source → graceful "does not resolve" info alert + empty records; real domain → A records + alerts; see registrar-card-known-mname-domains for the registrar. Update validation order: ownership → host format → target format (`*` or `^https?://` or `/path`) → self-redirect → loop → domain taken (project_domains) → duplicate host, with the record itself excluded — an unchanged re-save always passes. Cleanup = delete rows via the list's delete icon (React ConfirmModal, safe for CDP).
