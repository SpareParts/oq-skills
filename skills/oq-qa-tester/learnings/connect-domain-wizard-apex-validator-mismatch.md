**Trigger:** QA on the Connect custom domain wizard (`/admin/connect-custom-domain/?id=<marketId>`, endpoints `POST /admin/multishop/connect-custom-domain/submit/` and `…/dns-records/`), or on the create-market wizards' DNS step, with a bare apex domain such as `qa-shop.cz`.

**Rule:** The two steps validate the domain differently. `ConnectCustomDomainRequest` only checks `Length 4–255`, so submit accepts an apex domain and creates the row ("The domain has been saved."); `DnsRecordsRequest` carries `#[CustomDomainName]` whose regex `^[^.]+(\.[^.]+){2,}$` demands three labels, so the very next `dns-records` call answers 422 "Domain name is too short, perhaps missing leading www?" and step 2 renders "THE DNS CHECK COULD NOT BE PERFORMED" with an empty table (verified 2026-09-17, PR #44800). For the DNS-check assertions always send `www.<host>` (the handler normalizes it back to the apex, `payload.domain` echoes the bare host) — and report the apex dead end as a finding, not as a harness problem. Each successful `validate:1` call writes TWO `dns_validation_results` rows (`type` routing + emails) and refreshes `project_domains.routingValidatedAt` only for a row found by hostname that `isCustom()`; internal aliases are never touched.
