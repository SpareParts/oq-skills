**Trigger:** Seeding or QA'ing a domain redirection for a specific market (`POST /admin/dns-redirection/create/` with `{marketId, sourceServer, targetUrl}`) and getting `400 {"errors":{"marketId":"No market found with the given ID."}}` for a market you can see in the `markets` table.

**Rule:** `CreateRedirectionService::create` does `$channel->domain ?? throw RedirectionDoesNotBelongToChannelException`, and a market whose only active `project_domains` row is its internal `<projectId>-<marketId>.myshoptet.com` alias has a null Domain value object — so redirects can only be created for markets that have a CUSTOM domain row, and the error is byte-identical to the one a nonexistent market id produces. Pick the market first: `SELECT salesChannelId, marketId FROM project_domains WHERE projectId=<id> AND activeTo IS NULL AND isInternal=0 AND redirectionTargetPattern IS NULL`. Pre-existing behaviour (the provider reads the same null from `markets.domain` before CZ3MUL1-940), so report it as a limitation, not a regression of whichever domain PR is under test. Creation guards that DO hold, all 400: source = another market's live custom domain (legacy base-domain check, message misleadingly says "another client"), source = the channel's own domain (self-redirect), source = another market's apex custom domain (`DomainAlreadyConnectedException` from `ProjectDomainRedirectionWriter`).
