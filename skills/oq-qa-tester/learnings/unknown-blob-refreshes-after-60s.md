**Trigger:** Asserting "served from cache" (a row changed behind the cache is NOT yet visible) on a host whose `env:<host>` blob is the `unknown` kind, e.g. a `project_domains` redirect host or any non-project host.

**Rule:** The unknown blob's refresh marker is `now + 60 s` (expiry `now + 7200 s`); blob format in KeyDB is `e=<expiry epoch>&r=<refresh epoch>&f=j|{json}`. A second request more than a minute after the cold load re-resolves from MySQL and looks exactly like a cache miss (observed 2026-09-09: SQL retarget followed within a minute by the new target). Drive the cache-hit check in one shell script: `DEL` the key, cold request, retarget by SQL, re-request within seconds, then compare the blob's `r` value before/after (unchanged = hit). Full project / legacy `redirect_url` blobs refresh after 1 h and live 30 d, so there the same check is forgiving.
