**Trigger:** Seeding synthetic domains (project_domains / domain_redirects rows) to drive storefront domain resolution or redirects locally over HTTPS.

**Rule:** The dev proxy answers any `*.test` host but presents one cert, `CN=*.myshoptet.com.test`. Pick synthetic hosts of the shape `<label>.myshoptet.com` so `https://<label>.myshoptet.com.test` is cert-valid in Chrome (a `www.<label>.myshoptet.com.test` request is two labels deep and mismatches → interstitial; use curl -k or the `thisisunsafe` bypass). `project_domains.domain` may be seeded bare (`routing_domains_active` strips scheme/path/port itself); `routing_domains_active` requires `activeTo IS NULL AND isValid = 1`; `marketId` is NOT NULL (use any int for QA rows); tag QA rows with `context='{"qa":"<TICKET>"}'` and delete by that marker. The request host reaches `ProjectConstants` with `.test` already stripped, so Redis env keys are `env:<label>.myshoptet.com` — delete those at cleanup too (a fallthrough to "unknown project" caches ~2h).
