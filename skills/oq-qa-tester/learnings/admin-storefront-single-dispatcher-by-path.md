**Trigger:** Testing whether some domain-resolution or bootstrap logic in `cms/packages/Config/ProjectConstants.php` (or anything gated on `Environment::isFrontOffice()`/`isAdmin()`/`isAdminApi()`) behaves correctly for ADMIN vs STOREFRONT, on a domain that does NOT belong to any provisioned project.

**Rule:** Locally there is one physical entrypoint (`/var/www/cms4/index.php`, built from `setupPaths.php` + a small router) shared by every host: it `include`s `admin/index.php` when the URL's first path segment is `admin` or `admin-api` (or the host matches the OAuth-redirect pattern), otherwise `cms/index.php` — the decision is by URL PATH only, never by Host header or whether the domain resolves to a project. So hitting `<any-domain>.test/admin/login/` genuinely exercises the admin runtime (`Runtime::ADMIN`, `IS_FRONT_OFFICE=false` via `ServerVariablesMiddleware`, which runs before `EnvironmentSetupMiddleware` in `system.neon`) even for a domain with zero DB rows anywhere. This makes it a valid, drivable way to test admin/storefront boundaries on synthetic domains — no real project needed. See also `environment-cache-ignores-runtime` for why the FIRST request against a given domain can still determine what a later request of the other kind sees.
