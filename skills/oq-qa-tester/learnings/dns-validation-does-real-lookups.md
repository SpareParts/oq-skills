**Trigger:** Testing DNS validation flows (connect-custom-domain check, wizard DNS records, `dns_validation_results`) on the dev stack with a placeholder-looking domain such as `vasedomena.cz`.

**Rule:** The dev stack performs REAL DNS lookups (queries the domain's live nameservers), and `vasedomena.cz` is a real registered domain (dexus.cz NS, an A record, a CAA `0 issue "letsencrypt.org"`), so "absent record" scenarios silently turn into "existing record" scenarios and results are flaky per nameserver answer. To reproduce absent-record behavior use a clearly nonexistent domain (e.g. `www.neexistujici-domena-qa967.cz` → NXDOMAIN → all lookups empty). Successful `validate:1` calls write snapshot rows into `st_<projectId>.dns_validation_results` — delete the tested domains' rows at cleanup.
