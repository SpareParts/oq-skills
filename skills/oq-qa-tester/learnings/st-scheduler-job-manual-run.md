**Trigger:** A scenario needs a scheduler cron job executed for real on the dev stack (a PR touches `scripts/cron/*Job.php`).

**Rule:** Run it from the dev console: `st-scheduler-job <PROJECT_ID> <JOB_ID|JOB_CODE>` (`-l` lists jobs; job id/class in `st_cms.scheduler`). Pick PROJECT_ID from `st_cms.scheduler_projects WHERE jobId=<id>` — global jobs run under a fixed context (e.g. MoveToDomainJob = job 30 under project 46, the CRM context). The script executes `sudo -u www-data php cms/schedulerJob.php <jobId> <projectId> <domain> 0` directly (no queue) and streams the job's log lines to stdout — read PASS/FAIL evidence there plus the DB. Trap: it dies with "Make directory '/var/tmp/release/cms4-master/cache' writable" / "Unable to create file … Permission denied" when release cache dirs are root-owned (happens after root-context cache surgery) — fix with `chown -R www-data:ftp /var/tmp/release/cms4-master/cache` and rerun. `exec('/usr/local/bin/st-generate-rewrite-map')` inside jobs fails on `/mnt/apache` permissions locally — harmless noise after the DB writes, not a job failure.
