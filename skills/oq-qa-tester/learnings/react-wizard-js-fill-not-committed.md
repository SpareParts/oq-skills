**Trigger:** Filling a React wizard text input via the native value setter + `input` event (the 1Password-safe way), then submitting several steps later.

**Rule:** The step-level validation may pass (it reads current input state) while the final submit payload carries an EMPTY value — the wizard store commits on change/blur, not input. Concrete case: v2 create-market wizard submitted `domainAndName.name = ""` → 422 "musí mít délku alespoň 1 znaků" after the name step had validated fine. Always dispatch `input` + `change` + `blur` + `focusout`, and verify the actual submit payload/response (hook) before attributing a 422 to the product.

**2026-09-17 update (connect-custom-domain wizard, PR #44800):** On this wizard the JS native-setter fill did not reach react-hook-form at all — even with `input` + `change` + `blur` + `focusout` dispatched, the Continue click fired NO request and the step did not advance. What worked: `computer:triple_click` on the field followed by `computer:type`, then the card's Continue button — submit went through with the correct `domain`. So try the native-setter route first (1Password-safe), but when a submit silently does nothing and the fetch hook captured zero calls, fall back to real typing rather than assuming a product bug. The `computer:type` route also leaves the form dirty, which then blocks navigation and tab close — see dirty-react-form-blocks-navigate-and-tab-close.
