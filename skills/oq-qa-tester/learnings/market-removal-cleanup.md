**Trigger:** Cleaning up markets created during a run on a multishop dev shop.

**Rule:** The bare `DELETE /admin/multishop/market/remove/` fetch returns 400 (`ImpossibleToRemoveMarketException`); use the UI instead: market settings (`/admin/nastaveni-online-obchodu/?id=N`) → ODSTRANIT OBCHOD → type the exact market name into the confirm modal. Two driving traps (2026-08-25): the ODSTRANIT click races React hydration — click it only after the settings page settled and verify the modal actually appeared before typing; and the modal's name input REJECTS the JS native-setter route (React resets it, red "Zadejte prosím přesně" error) — it must be typed via `computer:type` into the focused field. The flow deletes the market, its `project_domains` row, AND (verified 2026-08-24) the channel's `sales_channel_currencies` + `sales_channel_languages` rows; the `sales_channels` row is soft-deleted (`deletedAt` set, name suffixed `~deleted~<id>`) and stays. What it does NOT clean: `options_variants` (≈52 rows/channel) and `product_sales_channel_visibility_restriction` (4 rows/channel) — delete those manually for the removed channel ids. Snapshot `SELECT COUNT(*) FROM options_variants` BEFORE creating any market (each new channel adds its ~52 rows immediately) so baseline restore is verifiable.

**2026-09-10 update:** On `multishop.myshoptet.com.test` the first REMOVE STORE click after the page load consistently did nothing (even after a 6 s wait); the second click opened the modal. The modal input accepts `computer:type` after a coordinate click on the field (~670,471) and the red DELETE STORE sits at ~905,542; the flow lands on the Online stores overview. Leftovers per removed channel this time: 80 `options_variants` and 16 `product_sales_channel_visibility_restriction` rows; `sales_channels` rows stay soft-deleted (`~deleted~<id>`), so the channel count never returns to baseline.

**2026-09-17 update:** A JS `click()` on the button whose text is `Remove store`, issued after a 2.5 s settle wait and with a one-time retry if no `[role="dialog"]` appeared, opened the modal on the first try; the name input still needs `computer:type` after a coordinate click. `DELETE /admin/multishop/market/remove/` answers **204** from the UI. Leftovers for a one-language (cs) / one-currency (CZK) market: 40 `options_variants` + 8 `product_sales_channel_visibility_restriction` rows. Since PR #44800 the market's internal `project_domains` row is CLOSED (`activeTo` set) on removal, not deleted — delete it yourself if the run must leave the table byte-identical.
