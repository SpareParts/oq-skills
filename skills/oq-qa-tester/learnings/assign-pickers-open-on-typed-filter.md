**Trigger:** Driving the "Přiřadit měnu" / "Přiřadit stávající jazyk" combobox on Market Settings or the create-market wizard via JS — `focus()`/`click()` opens no dropdown, `find` sees no options.

**Rule:** These pickers render their option list only after an `input` event; an empty-value focus/click sometimes works right after page load but not reliably later. Robust sequence per item: focus the search input, set a filter value via the native value setter (`Object.getOwnPropertyDescriptor(el.constructor.prototype,'value').set`), dispatch `input`, wait ~400 ms, then click the `li`/`[role="option"]` whose trimmed text equals the code. A real mouse click on the field (computer tool) also opens the unfiltered list on a freshly loaded page — but the typed-filter route works in both states, so prefer it.

**2026-09-17 update (v1 create-market wizard, "Assign existing language" / "Select currency"):** after the typed filter the options are `[role="option"]` elements whose only identity is the VISIBLE text ("Čeština", "CZK") — no `value` attribute — so match `textContent.trim()` against the label, not the code, and filter `offsetParent !== null`. A loose `li` selector catches the admin sidebar items and clicking one is a silent no-op. A real mouse click on the field opens the unfiltered list, but a ref click on an option that is not visible does not select it; the typed-filter + visible-text route worked for both pickers and switched the row's `Default` toggle on by itself.
