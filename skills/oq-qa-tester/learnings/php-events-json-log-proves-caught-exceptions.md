**Trigger:** A code path catches an exception and only logs it (`$logger->error(..., ['exception' => $e])`), so the HTTP response looks like a plain fallthrough and you need proof the catch fired — or you need to know whether an admin-vs-storefront gate skipped the call at all.

**Rule:** The Monolog `default` channel writes JSON lines to `/var/www_logs/php/php_events_json.log` inside `shoptet-www` (same file visible from the console container). Each line carries `context.exception.{class,message,file}` and `extra.{vhost,request,verb,request_id,messenger_command}`, so `grep -a "<message>" … | python3 -c` grouped by vhost/request gives a per-request count — the cleanest proof that (a) the catch fired and (b) which runtime triggered it (an `/admin/…` request with zero lines proves the `isFrontOffice()` gate held). Tracy files in `/var/tmp/exceptions/` dedupe by hash (one `exception--<hash>.md` per distinct exception), so their count never reflects request volume; use them for the stack trace only.
