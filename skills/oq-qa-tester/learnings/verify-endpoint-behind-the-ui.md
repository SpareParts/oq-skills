**Trigger:** A PR adds validation to a request validator and the scenario drives the corresponding admin UI flow.

**Rule:** Before concluding PASS/FAIL, map the UI page to the endpoint it actually posts to (grep the React page for its submit `url:`; admin pages often have v1/v2 endpoint pairs). Concrete case: the live Create Market wizard `/admin/pridat-online-obchod/` posts to v1 `/admin/multi-shop/wizard/submit/` (`CreateMarketRequestValidator`), while `/admin/pridat-online-obchod-v2/` posts to v2 `/admin/multishop/create-market-wizard/submit/` (`CreateMarketWizardSubmitRequestValidator`). A rule added only to one validator leaves the other endpoint as a live side door — test both the UI flow and the guarded endpoint directly (same-origin `fetch` from a logged-in admin tab works; no CSRF header needed on these Symfony-routed admin JSON controllers).
