**Trigger:** Driving Market Settings (`/admin/online-store-settings/?id=N`, cs slug `nastaveni-online-obchodu`) to exercise one specific write path — languages, currencies, basic information, primary-market switch.

**Rule:** The page posts ONLY the active tab's section; `MarketSettingsRequest`'s sections are each nullable and the orchestrator branches on them. Consequences: a Languages-and-currencies save runs `SetSalesChannelLanguagesCommand` (+ currencies), a Settings save runs `UpdateMarketScalarDataCommand` → `MarketBasicInformationChangedEvent` (and `SetMarketAsPrimaryCommand` when *Default store* is ticked). Those are different subscribers writing different option scopes, so **the wrong tab silently tests the wrong path**. Two driving traps: the first tab click after page load usually no-ops (hydration race) and a second click on the same ref then switches, so an even number of clicks lands you back on Settings — always screenshot (or check the URL for `#languages-and-currencies`) to confirm the active tab immediately before Save. `find` for the tab returns a usable ref, but a coordinate click on the tab label is the reliable fallback. The `Default store` checkbox ignores a ref click; click it by coordinate (~628,513 at 1440×1080). It renders grey-checked-disabled on the market that is already primary. Submit is `POST /admin/multi-shop/market-settings/submit/` → `200 {"code":200,"message":"OK"}`.
