**Trigger:** A storefront redirect on the dev stack (alias → canonical market domain, apex → www, secondary-market admin → primary admin) lands on `http://<host>.test/` although the code under test builds `https://` URLs.

**Rule:** Redirects that go through the legacy `Shoptet\Url\Redirector::redirectToProjectUrl()` (called by `ProjectRedirectMiddleware` via `UrlTranslateHelper`) force `$projectScheme = 'http'` when `DevelopmentHelper::isDevelopmentEnvironment()` is true, so the scheme is a dev artifact — assert the host, not the scheme. Redirects emitted by the code path itself (e.g. `ProjectDomainRedirectionResolver` → `StorefrontBaseUrlBuilder` for `project_domains` redirect rows) keep `https://`, which is the tell for which path produced a given 301. Verified 2026-09-17 on PR #44800.
