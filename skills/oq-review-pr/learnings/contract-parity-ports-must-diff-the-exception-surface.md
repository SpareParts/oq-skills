# A contract-parity port must be diffed against the target's exception→null mapping, not only its shapes

Why: a port whose stated goal is "callers won't change when the real module lands" invites a byte-compare of shapes (interface + DTO), but the shapes say nothing about which failures return `null` and which escape as exceptions. The service the adapter wraps documents only its declared `@throws`, while the repository layer underneath can wrap every other `Throwable` into its own lookup-failure exception and throw it on conditions the service never mentions (timeouts, non-NOERROR/NXDOMAIN rcodes) — so an adapter that catches only the declared exception leaks the underlying domain exception through the contract, while the future module catches its own failure exception and returns null. The drift is invisible at swap time: a caller written per the contract docs (null on failure) crashes today and silently starts working after the module lands. Diff the whole escape surface — walk to the implementation's actual throw set (repository/executor `@throws`, rcode and timeout handling), not the service-layer docblock — and pin the failure path with a test that stubs the wrapped service to throw the implementation's failure exception. Distinct from `catch-to-false-conflates-unreachable-with-answered-no` (there the caller erases a throw contract into a negative; here the port leaks an exception the target maps to null) and from `checked-exception-throws-ripple-to-every-transitively-throwing-caller` (a declared throw rippling statically; here the escape is undeclared, so the static walk never sees it).
Evidence: shoptet/cms4#48802 (MIN-1007 review round): the `RegistrarFinder` adapter caught only `InvalidDomainException`, but `DnsRecordsProvider::findRecordsInternal` wraps every other `Throwable` into `DnsLookupException` and `DnsQueryExecutor::assertUsableResponseCode()` throws it on any non-NOERROR/NXDOMAIN rcode, so a resolver failure escaped `findForHostname()`/`findForApexOf()` as a Multishop exception; the target module's `RegistrarFinder::find()` (#46186, head 6b39509bdc) catches its lookup-failure exception and returns null — ticket CZ3MUL1-1164's "DNS neodpovídá → null". Fixed by commit 1b5a3ba6c2 (both catches → null + stubbed-exception test).
